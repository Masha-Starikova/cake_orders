> **Обновление.** Деплой переехал с Cloudflare на свой VPS (Docker + Caddy,
> оплата в рублях). Упоминания Cloudflare, edge runtime и R2 ниже устарели.
> Актуальная версия: `docs-architecture.md` (система и порядок работ) и
> `docs-deploy-vps.md` (сервер и автодеплой). Этот файл оставлен как краткая

## 1. Целевая архитектура

```
Браузер (Next.js форма)
    │  POST /api/order  (JSON: OrderFormData + orderId)
    ▼
Cloudflare Pages Function (app/api/order/route.ts, runtime = edge)
    ├─ 1. валидация тела запроса (сервер не доверяет клиенту)
    ├─ 2. пересчёт цены на сервере (calculatePrice)
    ├─ 3. запись строки в Google Sheets  (Sheets API v4, service account JWT)
    ├─ 4. отправка сообщения в Telegram (Bot API sendMessage / sendPhoto)
    └─ 5. ответ клиенту { ok, orderId }
```

Принципы:

- **Сервер главный.** Цена, номер заказа и дата создания формируются на сервере.
  Клиент только показывает. Иначе любой может подменить сумму в запросе.
- **Sheets = база данных.** Telegram = уведомление. Если Telegram упал, заказ всё
  равно должен лежать в таблице. Если упала таблица, заказ должен всё равно уйти
  в Telegram, а ошибка записи должна быть видна.
- **Никаких npm-библиотек Google.** `googleapis` не работает в edge-runtime
  Cloudflare. Используем чистый `fetch` к REST API и Web Crypto для подписи JWT.
- **Секреты только на сервере.** Токен бота и ключ сервис-аккаунта никогда не
  попадают в клиентский код.

## 2. Google Sheets

### 2.1 Подготовка (делается руками, один раз)

1. Google Cloud Console → создать проект (например `cake-orders`).
2. Включить **Google Sheets API**.
3. IAM → Service Accounts → создать сервис-аккаунт. Скачать JSON-ключ.
   Из него нужны два поля: `client_email` и `private_key`.
4. Создать Google-таблицу. Скопировать её ID из URL
   (`https://docs.google.com/spreadsheets/d/<ЭТО_ID>/edit`).
5. Поделиться таблицей с `client_email` сервис-аккаунта с правами **Редактор**.
   Без этого шага API вернёт 403.
6. Записать в `.env.local` и в переменные Cloudflare Pages:
   - `GOOGLE_SHEETS_ID`
   - `GOOGLE_SERVICE_ACCOUNT_EMAIL`
   - `GOOGLE_PRIVATE_KEY` (многострочный; в Cloudflare вставляется как есть,
     в `.env.local` переносы заменяются на `\n`)

### 2.2 Структура листа `Orders`

Одна строка = один заказ. Первая строка — заголовки. Порядок колонок фиксируем
в коде, чтобы фронт и таблица не расходились.

| # | Колонка | Источник |
|---|---|---|
| A | Дата создания | сервер, ISO + МСК |
| B | Номер заказа | сервер |
| C | Статус | по умолчанию `Новый` (см. раздел 5) |
| D | Продукт | `productId` → название |
| E | Вес / кол-во | `weightKg` или `qty` |
| F | Начинка | `filling` |
| G | Тип декора | `decor.type` → название |
| H | Детали декора | `buildDecorSummary` в одну строку `label: value; ...` |
| I | Референс | ссылка (см. 2.4) или имя файла |
| J | Дата готовности | `dueDate` |
| K | Получение | Самовывоз / Доставка |
| L | Адрес | `address` |
| M | Имя | `name` |
| N | Телефон | `phone` |
| O | Instagram | `instagram` |
| P | Комментарий | `comment` |
| Q | Цена торта | сервер |
| R | Доплата за декор | сервер (или `по договорённости`) |
| S | Итого | сервер |
| T | Код для Direct | `ZAKAZ<orderId>` |

Второй лист `Log` (опционально): время, orderId, что удалось/не удалось
(`sheets: ok`, `telegram: fail: <текст>`). Полезен для отладки без доступа к
логам Cloudflare.

### 2.3 Как писать без библиотеки

Sheets API требует OAuth2 access token. Для сервис-аккаунта он получается по схеме
JWT Bearer:

1. Собрать JWT: header `{alg: RS256, typ: JWT}`, claims
   `{iss: email, scope: "https://www.googleapis.com/auth/spreadsheets", aud: "https://oauth2.googleapis.com/token", iat, exp: iat+3600}`.
2. Подписать `private_key` через `crypto.subtle.sign("RSASSA-PKCS1-v1_5")`.
   Ключ импортируется из PEM → PKCS8 (`crypto.subtle.importKey("pkcs8", ...)`).
3. `POST https://oauth2.googleapis.com/token` с
   `grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer&assertion=<jwt>`.
4. Получить `access_token`, использовать в заголовке `Authorization: Bearer`.
5. Добавить строку:
   `POST https://sheets.googleapis.com/v4/spreadsheets/{id}/values/Orders!A:T:append?valueInputOption=USER_ENTERED`
   с телом `{ values: [[...20 значений...]] }`.

Токен живёт час. На edge можно не кэшировать: один заказ = один токен. Это
дешёво и надёжно.

Файлы, которые появятся:

```
lib/server/google-auth.ts    — получение access token (JWT + Web Crypto)
lib/server/sheets.ts         — appendOrderRow(order) → маппинг в 20 колонок
```

### 2.4 Референс-фото

Сейчас файл хранится как base64 `referenceDataUrl` в состоянии формы.
Варианты:

- **A. Минимум (первый релиз).** В таблицу пишем только имя файла. Само фото
  отправляем в Telegram через `sendPhoto` (base64 → Blob → multipart).
  Кондитер видит картинку в чате, таблица хранит факт наличия.
- **B. Позже.** Загружать фото в Cloudflare R2, в таблицу писать публичную
  ссылку. Требует bucket + binding, отдельный этап.

Рекомендация: A. Ограничить размер файла на клиенте (например 5 МБ) и на
сервере, потому что body edge-функции ограничен.

## 3. Telegram

### 3.1 Подготовка

1. В Telegram открыть `@BotFather` → `/newbot` → получить `TELEGRAM_BOT_TOKEN`.
2. Куда слать уведомления: личный чат кондитера **или** приватная группа
   (лучше группа: можно добавить помощника, ставить реакции, отвечать в тред).
3. Узнать `chat_id`: добавить бота в группу, написать любое сообщение, открыть
   `https://api.telegram.org/bot<TOKEN>/getUpdates`, взять `chat.id`
   (для группы он отрицательный).
4. Записать `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` в env.

Бот на этом этапе **пассивный**: только отправляет. Webhook и приём команд не
нужны. Это резко упрощает первый релиз.

### 3.2 Формат сообщения

`parse_mode: HTML` (безопаснее Markdown, меньше проблем с экранированием).
Все пользовательские строки экранировать (`<`, `>`, `&`).

```
🎂 Новый заказ #CBH4821

Классический торт 3 кг
Начинка: Красный бархат
Декор: Надпись
  • Текст: С днём рождения
  • Цвет: розовый
Референс: 📎 фото ниже

📅 К дате: 14 сентября
🚚 Доставка: ул. Пример, 5
👤 Анна · +7 999 123-45-67 · @anna

💬 Комментарий: без орехов

💰 Торт 9 000 ₽ + декор 0 ₽ = 9 000 ₽

Код для Direct: ZAKAZ CBH4821
📊 Открыть таблицу
```

Если есть референс: `sendPhoto` с `caption` = тот же текст (лимит 1024 символа;
если длиннее, `sendMessage` + отдельный `sendPhoto`).

Файл: `lib/server/telegram.ts` — `notifyNewOrder(order, priceInfo)`.

### 3.3 Что делать, если Telegram недоступен

Не ронять заказ. Логировать, отдавать клиенту `ok: true` с флагом
`telegramSent: false`. Заказ есть в таблице, клиент получил номер.

## 4. Серверный эндпоинт `POST /api/order`

Порядок шагов внутри функции:

1. **Разобрать JSON.** Если не JSON или нет обязательных полей → 400.
2. **Валидация.** Перенести проверки из `validateStep` в `lib/validators.ts`
   (сейчас там заглушка `valid: true`). Одна функция, используется и на клиенте,
   и на сервере. Проверять: продукт существует, начинка разрешена для продукта,
   декор разрешён (`isDecorAllowedForProduct`), обязательные поля декора
   заполнены, дата не раньше завтра, телефон похож на телефон, при доставке есть
   адрес.
3. **Пересчёт цены** через `calculatePrice` из `lib/pricing.ts`. Клиентскую сумму
   игнорировать.
4. **Номер заказа.** Перенести генерацию из `handleSubmit` на сервер. Логику
   (`productCode + fillingCode + 4 цифры`) вынести в `lib/order-id.ts`, чтобы
   клиент и сервер использовали одну.
5. **Sheets append.** Ошибку ловим отдельно.
6. **Telegram send.** Ошибку ловим отдельно.
7. **Ответ.**
   ```json
   { "ok": true, "orderId": "CBH4821", "totalPrice": 9000,
     "sheetsSaved": true, "telegramSent": true }
   ```
   Если оба канала упали → 502 с `ok: false`, и клиент показывает
   «не удалось отправить, напишите в Direct».

Защита:

- Rate limit по IP через Cloudflare (Pages → Security → Rate limiting rules)
  или простая проверка `Origin`/`Referer`.
- Honeypot-поле в форме (скрытый инпут; если заполнен → молча 200 без записи).
- Лимит размера body (референс).

## 5. Изменения на фронте

Небольшие, но обязательные:

1. `handleSubmit` становится `async`: показать состояние «отправляем», сделать
   `fetch("/api/order", { method: "POST", body: JSON.stringify(formData) })`,
   взять `orderId` и `totalPrice` из ответа, только потом `setSuccess`.
2. Состояние ошибки отправки: отдельный экран/плашка с кнопкой «Повторить» и
   ссылкой на Direct.
3. Убрать генерацию `orderId` из клиента (или оставить как fallback, если сервер
   не ответил, но помечать заказ как неподтверждённый).
4. Кнопка отправки заблокирована, пока запрос идёт (защита от двойного клика и
   двух строк в таблице).
5. Лимит размера файла референса + понятная ошибка.
