# Google Sheets: подготовка и подключение по мелким шагам

Часть A и B делаются руками в браузере, один раз. Часть C на вашем Mac.
Часть D это код. Каждый пункт заканчивается проверкой: не идти дальше,
пока она не пройдена.

---

## Зачем всё это (теория в трёх абзацах)

Google не даёт программе писать в таблицу «просто так». Нужен пользователь,
от имени которого идёт запись. Заводить для этого свой личный аккаунт
нельзя: пришлось бы хранить пароль в коде. Поэтому Google даёт создать
**сервис-аккаунт**: технического пользователя без пароля и почтового ящика,
у которого вместо пароля есть приватный ключ.

Сервис-аккаунт живёт внутри **проекта Google Cloud**. Проект это просто
папка с настройками: какие API включены, какие технические пользователи
существуют. Биллинг для нашего случая не нужен: Sheets API бесплатен.

Таблица открывается сервис-аккаунту так же, как коллеге: кнопка
«Поделиться», вставить его e-mail, права «Редактор». После этого сервер,
подписав запрос приватным ключом, может добавлять строки.

```
Google Cloud проект
  └── Sheets API включён
  └── Сервис-аккаунт  cake-orders@....iam.gserviceaccount.com
        └── JSON-ключ  →  .env.local на Mac  →  .env на сервере

Google-таблица  ──поделиться──▶  e-mail сервис-аккаунта (Редактор)
```

## Часть A. Google Cloud Console (~15 минут)

Адрес: https://console.cloud.google.com. Войти под тем Google-аккаунтом,
которому будет принадлежать таблица. Лучше аккаунт кондитерской, а не
личный, чтобы потом не переносить.

- [x] **A1. Принять условия.** При первом входе Google просит выбрать страну
      и согласиться с условиями. Это не биллинг, карта не нужна.
- [x] **A2. Создать проект.** Вверху слева выпадающий список проектов →
      «Новый проект». Имя `cake-orders`. Организацию не выбирать. «Создать».
      Подождать 10–20 секунд, убедиться, что вверху выбран именно он.
      Проверка: в шапке написано `cake-orders`.
- [x] **A3. Включить Sheets API.** Меню слева → «API и сервисы» →
      «Библиотека». В поиске `Google Sheets API` → открыть → «Включить».
      Проверка: кнопка сменилась на «Управление».
- [x] **A4. Создать сервис-аккаунт.** Меню → «IAM и администрирование» →
      «Сервисные аккаунты» → «Создать сервисный аккаунт».
      Имя `cake-orders-writer`. Идентификатор подставится сам.
      «Создать и продолжить». Шаг «Роли» пропустить (роли в проекте не нужны:
      доступ к таблице выдаётся через «Поделиться», а не через IAM).
      Шаг «Доступ пользователей» пропустить. «Готово».
      Проверка: в списке появился аккаунт с e-mail вида
      `cake-orders-writer@cake-orders-XXXX.iam.gserviceaccount.com`.
- [x] **A5. Скопировать e-mail.** Этот e-mail понадобится дважды: для
      таблицы и для `.env.local`. Сохранить в заметки.
- [x] **A6. Создать ключ.** Нажать на аккаунт → вкладка «Ключи» →
      «Добавить ключ» → «Создать новый ключ» → тип **JSON** → «Создать».
      Браузер скачает файл `cake-orders-XXXX-abcdef.json`.
      Проверка: файл в папке «Загрузки», внутри есть поля `client_email`
      и `private_key`.
- [x] **A7. Спрятать ключ.** Это единственный секрет всей интеграции: кто им
      владеет, может писать в таблицу. Переместить файл из «Загрузок» в
      надёжное место (менеджер паролей или папка вне проекта). В репозиторий
      не класть никогда. Если ключ утёк: вкладка «Ключи» → удалить → создать
      новый.

Возможные проблемы:
- Google просит подтвердить телефон или включить биллинг при создании
  проекта. Телефон подтвердить, биллинг не включать. Если без биллинга
  не пускает, значит выбран тип аккаунта Workspace-организации; попробовать
  обычный gmail.
- Пункты меню могут называться чуть иначе в зависимости от языка интерфейса:
  «APIs & Services» → «Library», «IAM & Admin» → «Service Accounts».

## Часть B. Таблица (~10 минут)

- [x] **B1. Создать таблицу.** https://sheets.new под тем же аккаунтом.
      Назвать `Заказы the cake club`.
- [x] **B2. Переименовать лист.** Внизу вкладка «Лист1» → правой кнопкой →
      «Переименовать» → `Orders`. Именно латиницей: имя листа участвует в
      адресе запроса.
- [x] **B3. Заголовки.** В первую строку вписать 20 заголовков, по одному в
      ячейку A1…T1:

      ```
      Создан | Номер | Статус | Продукт | Вес/кол-во | Начинка | Декор |
      Детали декора | Референс | К дате | Получение | Адрес | Имя | Телефон |
      Instagram | Комментарий | Цена торта | Доплата за декор | Итого | Код Direct
      ```
      Быстрый способ: скопировать строку выше, в A1 нажать «Вставить»,
      затем «Данные» → «Разделить текст на столбцы» → разделитель `|`.
- [x] **B4. Закрепить строку.** «Вид» → «Закрепить» → «1 строка».
- [x] **B5. Статус как выпадающий список.** Выделить колонку C (щёлкнуть по
      букве) → «Данные» → «Проверка данных» → «Добавить правило» → критерий
      «Раскрывающийся список» → значения: `Новый`, `Подтверждён`, `В работе`,
      `Готов`, `Выдан`, `Отменён`. Цвета по вкусу. «Готово».
- [x] **B6. Формат колонок.** Колонка A (Создан) → «Формат» → «Числа» →
      «Дата и время». Колонки Q, R, S (цены) → «Числа» → «Число» без
      десятичных. Телефон (N) → «Обычный текст», иначе Google превратит
      `+7…` в формулу.
- [x] **B7. Второй лист `Log`.** Плюс внизу → новый лист → переименовать в
      `Log`. Заголовки: `Время | Номер | Событие | Детали`. Сюда сервер будет
      писать ошибки Telegram и Sheets.
- [x] **B8. Поделиться с сервис-аккаунтом.** Кнопка «Настройки доступа»
      справа вверху → вставить e-mail из A5 → роль **Редактор** → снять
      галочку «Уведомить» (ящика у него нет) → «Отправить».
      Проверка: e-mail в списке пользователей с ролью «Редактор».
      Без этого шага сервер получит 403.
- [x] **B9. Скопировать ID таблицы.** Из адресной строки:
      `https://docs.google.com/spreadsheets/d/`**`1AbC…xYz`**`/edit#gid=0`.
      Длинная строка между `/d/` и `/edit`. Сохранить в заметки.

## Часть C. Переменные на Mac (~5 минут)

- [x] **C1. Открыть `.env.local`** в корне проекта (создан на шаге 0, пустой).
- [x] **C2. Заполнить три строки** из JSON-ключа и таблицы:

      ```
      GOOGLE_SHEETS_ID=<из B9>
      GOOGLE_SERVICE_ACCOUNT_EMAIL=<client_email из JSON>
      GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEv…\n-----END PRIVATE KEY-----\n"
      ```
      `private_key` в JSON уже записан одной строкой с `\n` внутри. Копировать
      его целиком вместе с кавычками, ничего не переносить руками.
- [x] **C3. Проверить, что файл в `.gitignore`.** Команда `git status` не
      должна показывать `.env.local`. Он там с самого начала, но проверить
      стоит.

## Часть D. Код (мелкие шаги, каждый с проверкой)

Это план того, что будет написано. Порядок важен: сначала самое рискованное,
авторизация, потом остальное.

- [x] **D1. Получение токена.** Файл `lib/server/google-auth.ts`, функция
      `getAccessToken()`. Читает три переменные из `process.env`, собирает
      JWT, подписывает ключом, обменивает на токен у Google.
      Проверка: временный маршрут `GET /api/debug/google` возвращает
      `{ ok: true, tokenPrefix: "ya29." }`. Маршрут удаляется в D6.
      Типичные ошибки на этом шаге: `invalid_grant` (сломан ключ или время на
      Mac отстаёт), `invalid_client` (не тот e-mail).
- [x] **D2. Чтение таблицы.** Прежде чем писать, прочитать: запрос
      `GET .../values/Orders!A1:T1` с токеном. Должен вернуть заголовки.
      Проверка: тот же debug-маршрут показывает 20 заголовков.
      Ошибка 403 здесь означает, что B8 не сделан. 404: неверный ID.
- [x] **D3. Маппинг заказа в строку.** Файл `lib/server/sheets.ts`, функция
      `orderToRow(saved)`: превращает объект заказа в массив из 20 значений
      в порядке колонок. Плюс `safeCell()`: защита от `=`, `+`, `-`, `@`
      в начале текста.
      Проверка: юнит-тест на vitest с примером заказа. Без сети.
- [x] **D4. Запись строки.** Функция `appendOrder(saved)`: токен из D1,
      строка из D3, запрос `append`. Возвращает `{ ok, range }` или
      `{ ok, error }`, никогда не бросает исключение.
      Проверка: debug-маршрут пишет тестовую строку → она видна в таблице,
      даты и числа выровнены вправо (распознаны), телефон остался текстом.
      Тестовую строку потом удалить руками.
- [x] **D5. Лог.** Функция `appendLog(orderId, event, details)` на лист
      `Log`. Той же механикой, что D4.
- [x] **D6. Подключение к эндпоинту.** В `app/api/order/route.ts` после
      валидации и расчёта вызвать `appendOrder`. Результат сохранить, не
      бросать. Debug-маршрут удалить.
      Проверка: заказ через форму на `npm run dev` → строка в таблице.
      Сломать `GOOGLE_SHEETS_ID` → форма всё равно показывает успех,
      в консоли ошибка от Google.

Зависимости: D1 нужен всем. D3 не зависит от сети и может быть написан
параллельно. D6 ждёт шаг 2 из общего плана (эндпоинт с валидацией).

## Что будет в итоге

Заказ из формы → сервер → новая строка в `Orders` через 1–2 секунды.
Кондитер видит её с телефона, меняет статус в выпадающем списке.
Ошибки интеграций накапливаются в `Log`, а не теряются.

## Часть E. Витрины, подсветка и фильтры (сделано 12.10.2026)

Таблица «Заказы the cake club» разложена так, чтобы заказы не терялись и
с ними было удобно работать. Главный принцип: **строка заказа никогда не
переносится между листами**.

Причина жёсткая. Сайт дописывает новый заказ в первую пустую строку
диапазона `Orders!A:T`. Унесли строку на другой лист — в образовавшуюся
дыру упадёт следующий заказ. Поэтому Orders это единственный источник
правды, а всё остальное только показывает его содержимое.

### Листы

| Лист | Что показывает | Чем заполнен |
|---|---|---|
| `Orders` | все заказы, append-only | пишет сайт |
| `Log` | ошибки Sheets и Telegram | пишет сайт |
| `Blocked` | закрытые даты | перезаписывает `/admin` |
| `К подтверждению` | статус «Новый», по дате выдачи | формула `QUERY` |
| `В работе` | «Подтверждён» и «В работе», без контактов | формула `QUERY` |
| `К выдаче` | статус «Готов», всё для выдачи | формула `QUERY` |
| `Начинки` | сколько какой начинки нужно за период | `SUMPRODUCT` |
| `Финансы` | помесячно заказы, выручка, средний чек | `SUMPRODUCT` |

Витрины только для чтения: формула не принимает ввод и ничего не записывает.
Статусы меняются в самом листе Orders, удобнее всего через **режимы
фильтрации** «Новые», «В работе», «Готовые к выдаче». В режиме фильтрации
редактируется настоящая строка Orders, поэтому заказ сразу уходит из текущего
фильтра. У каждого человека свой режим, вид друг другу не сбивается.

### Подсветка

В Orders строка красится по срочности и статусу, правила именно в таком
порядке приоритета:

1. дата выдачи прошла, а заказ не выдан и не отменён — красный;
2. выдача сегодня или завтра — оранжевый;
3. далее цвет по статусу: Новый, Подтверждён, В работе, Готов, Выдан, Отменён.

В витринах колонка «К дате» красится по тем же двум первым правилам.

### Колонки U и V листа Orders

- `U` «Итог по факту» — согласованная сумма для заказов со сложным рисунком,
  у которых в колонке R стоит «по договорённости», а «Итого» занижено.
  Лист `Финансы` берёт `U`, если она заполнена, иначе колонку `S`.
- `V` «Заметки» — свободное поле.

Проверено: заполненные `U` и `V` не мешают дозаписи заказов в `A:T`.
Сайт в эти колонки не пишет никогда.

### Чего делать нельзя

- Вставлять и удалять колонки внутри `A:T` листа Orders. Свои колонки
  добавлять только правее `V`.
- Переименовывать листы `Orders`, `Log`, `Blocked`: запись оборвётся.
- Оставлять пустые строки внутри таблицы. Удалять строку целиком.
- Менять написание статусов. Формулы витрин сверяются с точными строками:
  `Новый`, `Подтверждён`, `В работе`, `Готов`, `Выдан`, `Отменён`.
  Обратите внимание на букву ё в двух из них.

### Известные ограничения

Заказ-ассорти из нескольких вкусов попадает в строку каждого своего вкуса
целиком: сайт не знает, сколько штук какого вкуса, это пишется в комментарий.
Поэтому сумма по строкам листа `Начинки` может быть больше строки «Итого»,
которая считается напрямую по заказам и ничего не задваивает.
