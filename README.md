# Cake Orders

Страница оформления заказа на торты. Оплата на сайте не предусмотрена: заказ будет записываться в Google Sheets и дублироваться уведомлением в Telegram. Деплой: свой VPS с оплатой в рублях, Docker + Caddy (см. `docs-deploy-vps.md`).

Сейчас интерфейс работает как 2-экранный лендинг: сначала показывается Hero-блок, затем по клику открывается карточка заказа.

## Технологии
- Next.js (App Router)
- React + TypeScript
- Docker + Caddy на VPS

## Локальный запуск
1. `nvm use`
2. `npm install`
3. `npm run dev`

> Node.js 20+. В Docker-образе используется Node 22.

## Проверка сборки в Docker
Так же проект собирается на сервере:
```bash
docker compose -f docker-compose.local.yml up --build
```
Сайт откроется на http://localhost:3000. Нужен запущенный Docker Desktop и файл `.env.local`.

## Переменные окружения
Скопируй `.env.example` в `.env.local` и заполни значения:
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`
- `GOOGLE_SHEETS_ID`
- `GOOGLE_SERVICE_ACCOUNT_EMAIL`
- `GOOGLE_PRIVATE_KEY`
- `ADMIN_PASSWORD` — пароль страницы `/admin`

## Закрытые даты (админ)
Страница `/admin` по паролю из `ADMIN_PASSWORD`. Календарь: клик по дню закрывает или открывает его для заказов, «Сохранить» пишет список в лист `Blocked` таблицы. Форма заказа получает список через `GET /api/blocked-dates` (кэш 1 минута) и не даёт выбрать закрытые дни; сервер проверяет дату повторно. Даты в листе `Blocked` можно править и руками.

## Начинки
Единый источник правды — `config/fillings.ts`: название, описание карточки и
ограничения по продуктам. Форма, валидация и генератор номера заказа берут
данные только оттуда.

Ограничения бывают двух видов:
- `excludedFillingsByProduct` — начинка есть у всех, кроме перечисленных
  продуктов (капкейкам недоступны «Молочная девочка» и «Медовик»);
- `onlyForProducts` у карточки — начинка доступна только этим продуктам.
  Так сделана «Киндер-Кантри»: торты, бенто и тортик в стаканчике, но не
  капкейки.

### Несколько начинок (ассорти)
Штучные продукты можно собрать из нескольких вкусов. Правило в
`multiFillingRules`: одна начинка на каждые `itemsPerFilling` штук, сейчас 3.
Получается 3 шт — 1 начинка, 6 шт — до 2, 12 шт — до 4. Сверху предел
ограничен числом доступных для продукта начинок. Сколько именно штук каждого
вкуса, клиент пишет в комментарии к заказу. Торты и бенто всегда с одной
начинкой. Чтобы поменять правило, достаточно поправить `itemsPerFilling`.

В заказе начинки хранятся массивом `fillings`, а в таблицу и в Telegram
уходят одной строкой через запятую.

## Черновик заказа
Форма сохраняется в `localStorage` (`lib/client/draft.ts`): при обновлении
страницы, обрыве связи или случайном закрытии вкладки заполненные поля и
номер шага восстанавливаются. Черновик живёт сутки, стирается после успешной
отправки и по кнопке «Начать заново». Если хранилище переполнено фото-
референсом, черновик сохраняется без фото, но с данными формы. При изменении
структуры `OrderFormData` нужно увеличить `DRAFT_VERSION`, тогда старые
черновики просто игнорируются.

## Как работает отправка заказа
UI формы → `POST /api/order` → валидация и расчёт цены на сервере → запись в Google Sheets + уведомление в Telegram → экран успеха.

Подробно: `docs-architecture.md` (система и порядок работ), `docs-deploy-vps.md` (сервер и автодеплой).

## Деплой
Свой VPS, Docker + общий Caddy на несколько проектов. Пошагово в `docs-deploy-vps.md`.

Что реально работает сейчас: Selectel, сервер «Poli» в Москве,
**1 vCPU / 2 ГБ RAM / 25 ГБ**, Ubuntu 24.04, домен и DNS там же.
Конфигурация вдвое скромнее, чем планировалось: `next build` на 2 ГБ не
проходит без swap, поэтому swap обязателен (раздел 4.3 в `docs-deploy-vps.md`).

2. Включи Device Toolbar (иконка телефона/планшета).
3. Прогони размеры: iPhone SE, iPhone 12/13/14, Android 412×915.
4. Проверь: переносы текста, поля не обрезаются, кнопки видны и удобно нажимаются (минимум 44px).
